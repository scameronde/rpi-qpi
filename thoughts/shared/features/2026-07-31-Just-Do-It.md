# Feature Brief: Just Do It

## System Context

**Project**: rpiqr (ORBIT) — Claude Code Workflow Toolkit

**Core purpose**: A structured agentic development pipeline that takes work from intent to reviewed, committed code through explicit, durable artifacts at every stage. Four entry points exist today — `/mission-architect` (greenfield), `/feature-architect` (brownfield), `/change-architect` (small changes), and the optional `/prototype` — all converging on the single execution path `/fact-finder → /planner → /implement`.

**Relevant existing components**:
- `/change-architect` — the fourth entry point, added in the previous release cycle; writes a typed Change Brief to `thoughts/shared/changes/` in a handful of questions, deliberately the cheapest artifact in the pipeline (`change-architect/SKILL.md:12`)
- `/change-architect`'s `## Open Questions for Fact-Finder` section — the brief's last substantive section, whose pre-write checklist today demands **at least one** entry (`change-architect/SKILL.md:122,187-192`)
- `/fact-finder` — the Ist-Bestimmung: spawns worker sub-agents, produces a cited research report
- `/planner` — 964 lines of skill producing a wave-decomposed plan plus a STATE file, with evidence verified by further sub-agents
- `/implement` — wave orchestration, Boundary Check, per-task review gate, one commit per task with its STATE update amended in (`implement/SKILL.md`)
- The plan/STATE sibling-file convention — a write-once artifact accompanied by a mutable state file whose `status:` describes the *work* rather than the document (`CLAUDE.md`, Plan File Format)
- `implement/reviewer-prompt.md` — one of four readers of the plan task-field contract (`CLAUDE.md`, Plan File Format)
- `/commit` — the sole precedent for `disable-model-invocation: true`, justified by writing git history (`commit/SKILL.md:4`)

## Feature Vision

The method ORBIT teaches is a three-beat figure: **Zielbestimmung**, **Ist-Bestimmung**, then a plan carrying the system from Ist to Ziel. `/change-architect` closed the last gap in the first beat — every route now begins with a recorded target state. But it closed that gap by adding an entry point to a path whose *execution* end was sized for something much larger.

For the smallest work the arithmetic is unforgiving. A three-line fix pays `/fact-finder` (worker sub-agents plus a cited report), then `/planner` (wave decomposition, evidence verification, plan plus STATE), then `/implement` (waves, baseline capture, Boundary Check, review gate) — on the order of twenty cold contexts, each re-reading `CLAUDE.md` and walking the DOX tree, to produce a diff a competent reader takes in at a glance. Every one of those stages earns its cost on work that needs it. None of them earns it here.

What happens instead is the failure this feature exists to prevent. Faced with that price for a typo fix, the honest user does not follow the path — they describe the change in chat and let the model do it. No brief, no record, no independent review, nothing in the artifact trail. That is precisely the gap `/change-architect` was built to close, reappearing at the other end of the same path: intent living in a session that vanishes. A cheap path that nobody walks does not close a gap; it only makes the gap harder to see.

`/just-do-it` is therefore not an escape from the pipeline — it is what stops people escaping it. It keeps the one beat that cannot be given up (a target state written *before* the work, checked afterwards by a context that did not do the work) and drops only the planning apparatus between them. The design's whole weight sits on the gate: a bypass that is cheaper will attract everything, so eligibility is decided in the brief, recorded in a frontmatter field, enforced as a hard refusal, and re-checked against three numeric bounds during execution. Without that, the route is a discretionary shortcut, and in three months it is the normal case with nobody having decided that evidence and review were optional.

## Target Users

**Primary users of this feature**:
- ORBIT users making changes small enough to hold in one head — a typo, a wrong constant, a renamed field, a one-site fix — who today either pay the full pipeline price or leave the pipeline entirely.

**Impact on other users** (if applicable):
- Auditors reading the artifact trail gain a recorded, reviewed outcome for small work that previously left only a bare commit, plus a visible record of the fast path's *failures* (`status: abandoned`) from which the gate's calibration can be judged.
- Users on the greenfield, brownfield and full change paths are unaffected: `route: full` is the default and every existing stage behaves exactly as before.

## Feature Value Proposition

A change small enough to hold in one head is documented, executed, independently reviewed and permanently recorded in one motion — at a cost proportional to the change, without stepping outside the artifact trail.

## Essential Capabilities

1. **A second exit from the change path, gated in the brief**
   - **What it enables**: The Change Brief gains a frontmatter key `route: direct | full`. `direct` is permissible only when **both** hold: `## Open Questions for Fact-Finder` is empty (written as the literal `none — nothing must be established before the change`) and `## Acceptance Criteria` carries exactly one entry. `/change-architect`'s existing elicitation question — *"Anything you're unsure about that the research should settle?"* — becomes the router; only its handling changes, not the conversation.
   - **Why it's essential**: The decision belongs where the intent is still fresh, and it must land in the artifact rather than in a judgment call at execution time. An empty Open Questions section is already the honest signal that no Ist-Bestimmung is needed — the gate reuses a condition the format states rather than inventing a size metric nobody can apply before looking.

2. **`/just-do-it` — bounded direct execution with one independent review**
   - **What it enables**: A skill that reads a `route: direct` brief, reads only what the change requires, makes it in the main session on the session model, and submits the diff to exactly **one** reviewer sub-agent in a fresh context — covering spec compliance against the brief and code quality together. One dispatch replaces roughly twenty. It refuses any brief not carrying `route: direct`, refuses a brief that already has a Change Record, and applies `/implement`'s branch rule: no work on `main`/`master` without explicit consent.
   - **Why it's essential**: This is the one beat that cannot be dropped. ORBIT's core guarantee is that a context which did not do the work checks it against an intent recorded beforehand. Removing planning leaves that guarantee intact; removing the review would make the route a different thing wearing ORBIT's name.

3. **Numeric bounds that keep the gate honest after admission**
   - **What it enables**: Three checkable limits, each with a defined escalation. More than roughly five files must be read, **or** more than one site implements the behaviour → stop before changing anything. The diff exceeds roughly fifty changed lines → discard and stop. The reviewer returns Critical or Important → exactly **one** fix round, then re-review; a second failure discards the working tree. Every escalation routes the brief to `/fact-finder` for the full path.
   - **Why it's essential**: `route: direct` is a claim made before anyone looked at the code. Without bounds that can contradict it during execution, the claim is never tested and the gate degrades into a formality. The single-implementation-site test is the sharpest of the three: a behaviour with two homes is exactly what makes a change stop being small. The one-round fix cap is what keeps a fast path from silently costing more than the full one.

4. **A Change Record that survives, including on abandonment**
   - **What it enables**: A sibling file `thoughts/shared/changes/YYYY-MM-DD-[Change-Name]-RECORD.md`, mirroring the established plan/STATE pairing, holding the changed files, the single acceptance criterion with its named evidence, and the reviewer's verdict. It is written and committed on **every** outcome — `status: complete` or `status: abandoned`, the latter naming what tripped which bound and where the work went.
   - **Why it's essential**: Without it the reviewer's verdict exists only in a sub-agent report that dies with the session, and "did this brief run, and did it pass?" becomes git archaeology. Recording abandonment is what makes the feature self-monitoring: if `status: abandoned` accumulates, the gate is mis-calibrated and that is visible rather than suspected. A fast path whose failures leave no trace is a fast path nobody can audit.

## Explicit Non-Goals

- **A fifth entry point**: The entry remains `/change-architect`. This is a second *exit* from the change path. Every pipeline-ordering location must present it that way — four entry points, two exits on the change route — because a fifth eingang in the diagram implies a fifth kind of intake, and one of them would quietly bypass the whole pipeline.
- **A direct route for feature briefs, missions, or epics**: Only change briefs can carry `route: direct`. Larger intent, by construction, cannot satisfy the two admission conditions.
- **Reusing `implement/reviewer-prompt.md`**: `/just-do-it` gets its own reviewer prompt. That template is a contract with exactly four readers over the plan task fields `Instruction`, `Done When` and `Verify` (`CLAUDE.md`, Plan File Format); a fifth reader with no task fields at all would dilute the contract rather than save work. It stays at four.
- **Any change to `/fact-finder`, `/planner` or `/implement` behaviour**: All three are untouched. In particular `/planner`'s admission gate keeps working unchanged, because a `route: full` brief travels exactly the path it does today.
- **Forbidding `/fact-finder` on a `route: direct` brief**: Escalating to more rigour is never an error. A user who changes their mind and wants evidence and a plan may take the full path from a `direct`-routed brief without ceremony, and no stage complains.
- **A `commit:` frontmatter field in the Change Record**: The Record is committed together with the change, so it cannot carry its own commit's SHA, and `/implement`'s amend pattern would invalidate a recorded one. Linkage runs upward through `change-brief:` and downward through `git log -- <record path>`. No field that can go stale.
- **Retrofitting**: `thoughts/shared/changes/` does not exist yet — no brief has ever been written. There is nothing to migrate, and `route:` is required on new briefs from the start rather than being optional-for-compatibility.
- **An unlimited fix loop**: Deliberately unlike `/implement`, which iterates until the reviewer passes. One round, then abandonment.
- **Waves, task decomposition, or a mutable state file**: `/just-do-it` executes one change in one motion. There is no `Wave:`, no task IDs, no resume path, and the Record is write-once rather than fortgeschrieben like a plan's STATE.
- **`presentation/ORBIT.pptx`**: Following the precedent of the `/change-architect` run, the deck in scope is `presentation/The_Agentic_Assembly_LineV3.html`; the binary `.pptx` files are not edited.

## Success Criteria

- [ ] `/change-architect` writes `route: direct` when the conversation ends with nothing for the research to establish and exactly one acceptance criterion, and `route: full` in every other case — and never mentions the cheaper path while eliciting open questions.
- [ ] `/just-do-it` refuses, without changing any file, a brief whose `route:` is `full`, absent, or malformed, and refuses a brief that already has a Change Record.
- [ ] A `route: direct` brief for a genuine one-site fix results in one commit containing the change and its Change Record, the Record naming the reviewer's verdict and the single acceptance criterion with its evidence.
- [ ] A brief that trips any of the three bounds — files read, implementation sites, diff size — or fails review twice leaves the working tree clean, writes a Record with `status: abandoned` naming the bound that tripped, and points the user at `/fact-finder`.
- [ ] Every pipeline-definition location states four entry points and two exits on the change path — verifiable by reading them side by side, with none of them showing a fifth entry point.
- [ ] `/fact-finder`, `/planner` and `/implement` run a `route: full` change brief exactly as they do today, with no new branch reached.

## Assumptions

**About the existing system**:
- ORBIT has no mission or spec document. Both `thoughts/shared/missions/` and `specs/` are empty, so `mission-source:` and `spec-source:` above read `none`; `CLAUDE.md` and the `SKILL.md` files were used in their place, and the one constraint resting on that substitution is marked `inferred`.
- `thoughts/shared/changes/` does not exist on disk. `PLAN-010` registered it in both governance files without creating it, so the directory is created by the first brief written. `/just-do-it` must not assume it exists.
- The count of "five places" for the pipeline definition is `CLAUDE.md`'s own claim. The preliminary grep for this brief found routing statements in `change-architect`, `feature-architect`, `mission-architect` and `prototype` `SKILL.md` files as well, which the five-place framing folds into "the affected `SKILL.md`". The fact report should enumerate rather than count.
- The three numeric bounds (≈5 files, 1 implementation site, ≈50 changed lines) are this brief's proposal, chosen so each is checkable during execution. They are not derived from measurement, and the Records they produce are the data that would justify changing them.

**About users**:
- A user who reaches for a one-line fix will accept a short brief plus one review round, but not a fact report and a plan. This is the premise the whole feature rests on — if it is wrong, the route is bypassed rather than followed, exactly as the current situation is bypassed.
- A user asked what the research must establish will answer honestly when the question carries no price signal. If that assumption fails, the gate measures intent to skip rather than size of change, which is why the new Non-Negotiable above is load-bearing rather than stylistic.

## Conversation Summary

- **Initial idea**: Some changes are small enough that neither a fact report nor a plan is warranted — one wants to document the change and let the model carry it out directly, since Opus and Sonnet are usually capable enough. Framed initially as a fifth entry point.
- **Refinements**: The framing was corrected twice. It is a second *exit* from the change path rather than a fifth entry point, because the intake is unchanged. And the real design problem was identified as the gate rather than the path: a cheaper bypass attracts all work, so without a mechanical admission test the pipeline's evidence and review stages are abandoned in practice without anyone deciding to abandon them. The gate was then found to exist already in the artifact format — `## Open Questions for Fact-Finder`, today required to be non-empty, is exactly the signal that no Ist-Bestimmung is needed when it is honestly empty. Four decisions were settled: only planning is skipped and one reviewer sub-agent is kept; the executor is a new skill named `/just-do-it` rather than a polymorphic `/implement` or an execution phase inside `/change-architect`; admission is a `route:` frontmatter field permitted only under two mechanical conditions; and execution is recorded in a sibling Record file that is also written on abandonment. A flaw in the agreed Record format was caught during synthesis: a `commit:` field cannot hold its own commit's SHA when Record and change land together, and `/implement`'s amend pattern would invalidate a recorded one — the field was dropped rather than made unreliable.
- **Key boundary decisions**: The review is not negotiable — dropping it was offered and declined, on the reasoning that a context which did not do the work checking against an intent recorded beforehand is ORBIT's core guarantee rather than one of its conveniences. The fix loop is capped at one round, unlike `/implement`'s iterate-until-green, so a fast path cannot silently cost more than the full one. Abandonment writes and commits a Record, making the gate's own calibration observable instead of a matter of opinion. `implement/reviewer-prompt.md` is not reused, keeping its four-reader contract at four. And the new Non-Negotiable forbidding any price signal when eliciting open questions was added on the observation that a gate whose condition the user is paid to answer falsely measures nothing.

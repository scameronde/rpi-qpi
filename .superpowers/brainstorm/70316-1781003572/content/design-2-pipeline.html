Design: Workflow Pipeline

Section 2 of 4 — how each stage flows in the new structure

Greenfield pipeline

/mission-architect → /specifier → /epic-planner → /researcher → /planner → /subagent-driven-development
All invocations are now Skill calls — user types /skill-name or Claude invokes proactively

What each Skill does internally

Skill Claude's role Agent calls Output
mission-architect Conversation with user None thoughts/shared/missions/
feature-architect Conversation + light scan Spawns codebase-locator thoughts/shared/features/
specifier Reads mission, writes spec None thoughts/shared/specs/
epic-planner Reads spec, writes epics None thoughts/shared/epics/
researcher Orchestrates research Spawns codebase-locator, codebase-analyzer, codebase-pattern-finder, web-search-researcher — results isolated thoughts/shared/research/
planner Reads research, writes plan Spawns codebase-analyzer for evidence — results isolated thoughts/shared/plans/
subagent-driven-development Orchestrates per-task loop Per task: general-purpose implementer → general-purpose spec reviewer → general-purpose quality reviewer Git commits per task
⭐ Highlighted rows are where isolation matters most — Agent calls keep heavy file work out of main context.

Skill anatomy — what each Skill file looks like

skills/researcher/SKILL.md
--- name: researcher description: Map codebase relevant to a spec or question. Spawns codebase agents for isolation. Outputs to thoughts/shared/research/ --- # Researcher [instructions for Claude on how to orchestrate the research phase] ## Agent Calls Spawn codebase-locator, codebase- analyzer, web-search-researcher via the Agent tool. Pass only the specific query — results return as research findings, not raw file dumps.
skills/subagent-driven-development/SKILL.md
--- name: subagent-driven-development description: Execute plan task-by-task via subagents with review after each --- # SDD [per-task loop instructions] ## Per task: 1. Spawn general-purpose implementer with full task text + context 2. Spawn spec reviewer 3. Spawn quality reviewer 4. Commit, advance to next task ## Prompt templates: ./implementer-prompt.md ./spec-reviewer-prompt.md ./code-quality-reviewer-prompt.md

Three Approaches

All three eliminate Commands and the IC/Coder problem. They differ in hook infrastructure and how researcher/planner are handled.

A

Pure Skills, no hook

All orchestrators become Skills. Skills instruct Claude to spawn general-purpose agents for heavy work. No Commands, no hook infrastructure.

Keeps
  • 6 worker agents (Explore type)
  • SDD skill for implementation
Removes
  • All 7 Commands
  • IC + Coder agents
  • 5 orchestrator agents
Files: 7 Skills + 6 worker agents = 13 files (was 25)
Trigger: User types /researcher → Claude loads Skill, spawns agent
No hook needed — Claude Code discovers skills natively
✓ Simplest ✓ No new infrastructure ~ Skill instructions in main context
B

Pure Skills + SessionStart hook (Recommended)

Same as A, but adds a hook that injects skill awareness at session start — like Superpowers itself does. User gets automatic discovery without needing to know skill names upfront.

Adds vs. A
  • hooks/session-start script
  • hooks/hooks.json
  • Auto-bootstrap at session start
Same removals
  • All 7 Commands
  • IC + Coder agents
  • 5 orchestrator agents
Files: 7 Skills + 6 worker agents + 2 hook files = 15 files
Trigger: Hook injects "you have these skills" at start → Claude knows what to invoke
Hook injects: list of available skills + when to use each
✓ Best UX ✓ Superpowers-aligned ~ Small hook to maintain
C

Skills trigger dedicated Agent files for heavy stages

Lightweight orchestrators (mission-architect, specifier, epic-planner, feature-architect) become Skills. Heavy stages (researcher, planner) remain as Agent files — but Skills trigger them, no Commands.

Keeps
  • researcher.md agent file
  • planner.md agent file
  • 6 worker agents
Removes
  • All 7 Commands
  • IC + Coder agents
  • 3 orchestrator agents
Files: 4 Skills + 2 orchestrator agents + 6 worker agents = 12 files
Trigger: Skill says "call Agent(subagent_type: 'researcher', …)"
Benefit: researcher/planner instructions never in main context
✓ Max context efficiency ~ Mixed Skills + Agents model ✗ More files, inconsistent pattern
What all three share:
  • No Commands directory
  • No IC agent, no Coder agent — SDD skill handles implementation
  • 6 worker agents (Explore type) preserved for write-safety guarantee
  • Context isolation via Agent tool calls, not file structure

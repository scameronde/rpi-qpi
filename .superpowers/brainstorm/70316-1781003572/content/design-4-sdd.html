✅ After: SDD Skill
Claude (main loop) reads SDD Skill
Reads plan, extracts all tasks
↓ per task
1. Implementer (general-purpose, fresh context)
Implements + tests + commits + self-reviews
2. Spec Reviewer (general-purpose, fresh context)
Verifies code matches spec — not just the report
3. Quality Reviewer (general-purpose, fresh context)
Checks clean code, tests, structure

What the SDD Skill contains

SKILL.md
  • Per-task loop instructions
  • Model selection guidance (Haiku for simple tasks)
  • Status handling (DONE / BLOCKED / NEEDS_CONTEXT)
  • Retry logic
Prompt templates (3 files)
  • implementer-prompt.md
  • spec-reviewer-prompt.md
  • code-quality-reviewer-prompt.md
Claude reads these and embeds the content into each Agent tool call

Model selection — token efficiency

Task type Model Example
1–2 files, clear spec Haiku (cheapest) Add type annotations, rename function
Multi-file, integration concerns Sonnet Add new API endpoint with tests
Architecture, design judgment Opus Refactor auth middleware
What this buys you vs. IC/Coder:
  • Each task gets a truly fresh context — no accumulated state from previous tasks
  • Two review gates per task catch spec drift and quality issues before the next task starts
  • No Bash escape hatch — implementer has Edit/Write/Read only, no Bash
  • Model can be sized to task complexity — cheap tasks use cheap models
  • Self-contained prompt templates make the behaviour transparent and editable
